EOPPP 컴파일러

석사 학위논문 · 2025.03 – 2026.06 · 단독

128개 코어가 단일 클록에 동기 동작하는 MIMD FPGA 프로세서를 표준 C로 프로그래밍할 수 있게 만든 컴파일러입니다.

문제

  • 코어 간 공유 메모리도 프로그램 카운터도 없어, 매 사이클 각 코어의 연산을 직접 기술해야 했음
  • mesh 통신 범위가 ±16이라 코어 하나를 옮기면 이웃 선택 비트마스크 수십 개를 재계산
  • 하드웨어가 오류를 보고하지 않아, 필드 한 비트가 틀려도 그대로 로드되어 잘못된 결과 산출
  • 30-tap FIR 필터 하나가 코어 엔트리 90개 이상 필요

접근

  • 새 언어를 만들지 않고 GCC의 C 프론트엔드와 GIMPLE/SSA를 재사용 — 각 식이 고정된 코어에서 한 번 평가된다는 실행 모델과 SSA의 구조가 일치
  • 제약을 넘는 코드가 조용히 오답을 내는 하드웨어라, 코드 생성 이전에 매핑 가능 여부를 판정하는 검사기를 별도 설계
  • 외부 도구가 아니라 GCC 파이프라인 내부에서 실행되는 3계층 구조

C 한 줄이 코어 명령이 되기까지

cur = p0 + p1;              # C
cur_3 = p0_1 + p1_2;        # GIMPLE SSA
core r0 : ADD  src=[r4,r5]  # 코어 배치
Z = 0x0000                  # 명령
Y = 0x00300000              # 이웃 마스크

# mask bit = 16 + (src − dst)
# r4,r5 relative to r0 → bit 20,21

막혔던 지점

모든 코어가 같은 사이클에 읽고 쓰므로 b = a 복사가 a의 새 값을 읽지 못함

a가 같은 사이클에 이항식으로 정의되면 복사 대상의 소스 리스트를 두 피연산자로 확장해 같은 합을 직접 계산

탭 그룹 30개를 연속 배치하면 전체 스팬이 누산기 마스크 범위(±16)를 초과

누산기를 담당 그룹들의 한가운데에 배치해 앞뒤로 분할 — 부분합 전송은 항상 ±16 안에 유지

goto는 GIMPLE에서 정규화되고 미사용 변수는 제거되어 검출 불가

검사기를 GCC 프론트엔드 이전(소스)과 SSA 변환 이후(GIMPLE) 두 단계로 분리

GPU SpMM 커널 전처리 최적화

ICTC 2026 투고 예정 · 단독

CUDA Core 기반 SpMM 최고 성능 커널 RoDe를 커널 수정 없이 전처리만으로 개선한 연구입니다.

먼저 실패했습니다. RoDe에 Stream-K를 적용해 SM 간 로드 밸런싱 개선을 시도했으나, 행마다 nnz가 균일하지 않아 균등 분할해도 실제 연산량이 다르고, 행 경계를 넘어 분할하면 cross-row atomicAdd의 직렬화 비용이 이득을 상쇄했습니다. Stream-K의 전제인 “작업 단위가 균질하고 독립적”이 SpMM에서는 성립하지 않는다고 판단해, 커널을 수정하지 않는 전처리 방향으로 전환했습니다.

행렬별 segment 길이 선택

  • 고정값 512가 전체 행렬의 25~28%에서만 최적
  • {256, 512, 1024} 중 행렬마다 선택
  • RoDe 기존 API를 호출하므로 소스 수정 불필요

chunk 단위 residue 행 정렬

  • 16행 윈도우 안에서 nnz 내림차순 정렬
  • 전역 정렬은 CSR 지역성을 해치므로 지역 윈도우로 제한
  • 전처리 시간 평균 0.1ms 미만

모델 경량화 연구

논문 4편 · 2024 – 2025

정밀도와 희소성을 바꿔가며 모델을 어디까지 줄일 수 있는지 측정했습니다.

RoBERTa · ICTC 2024 · 전자거래학회 2024

  • Pruning으로 sparsity를 0~99%까지 변화시키며 AMP 적용/미적용 교차 비교
  • 전 구간에서 정확도 차이 없이 학습 시간 38% · 메모리 24% 절감
  • 정확도를 좌우하는 것은 AMP가 아니라 모델과 데이터셋 특성이라고 결론

YOLOv8 · 전자거래학회 2024

  • AMP 적용 여부와 양자화(half precision, int8) 조합별로 크기 · mAP50-95 · 추론 시간 · FPS 비교
  • int8은 정확도 하락 폭이 큼
  • AMP + half precision 조합이 정확도·속도 균형에서 우위

지식 추적 모델 · ICOIN 2025

  • RTX 4090 서버와 Raspberry Pi 400에서 AMP 적용 여부까지 나눠 파인튜닝 후 추론 비교
  • 정확도는 두 환경에서 거의 동일
  • attention 계열은 저전력에서 추론 시간 2배 이상 증가

혼합 정밀도 연산 · 한국통신학회 2024

  • FP16의 좁은 표현 범위와 텐서 코어 기본 RZ 반올림을 손실 원인으로 정리
  • FP32↔FP16 잔차 분리, 가수 21번째 비트 추가, 암시적 비트, RN 반올림 네 기법 비교

SpMM 커널 비교 분석

ICTC 2025 · 단독

희소 행렬 곱셈 커널을 데이터 특성별로 테스트해 선택 기준을 정리한 연구입니다.

  • cuSPARSE · Sputnik · RoDe · FlashSparse · DTC-SpMM 5종을 구조 / 크기 / 희소성 3축으로 비교 (RTX 4090)
  • Tensor Core 계열이 모든 구조에서 CUDA Core 계열보다 우수, cuSPARSE는 비연산 오버헤드로 최하위
  • FlashSparse가 가장 빠르나 극단적 rectangular 행렬에서 행-열 불균형으로 segfault 발생 — 속도와 견고성의 트레이드오프 확인
  • 이 벤치마킹에서 RoDe를 개선 대상으로 선정해 위 전처리 최적화 연구로 이어짐
